## Data and provider decisions

- **Profile photos:** reuse `pt_profile_media`. Its existing policies restrict writes to the authenticated user's folder and allow public image reads. The picker explains visibility. UI limit: 5 MB; JPG, PNG, WebP. Files receive unique names so failed replacements do not overwrite existing images. Check-in photos continue using their private bucket.
- **Timezones:** use valid IANA identifiers, searchable through the browser's list control, with an explicit device-timezone action. Invalid values cannot be saved.
- **Push:** preference storage and a backend helper do not establish device registration. The UI now says unavailable. Live email, push, and wearable delivery were not certified or changed.
- **Workout units:** set logs have no unit column. Training charts obtain the recorded unit from the assigned exercise snapshot, using actual, configured, then default units. Ambiguous or absent units are excluded from numeric comparisons instead of guessed.
- **Nutrition ownership:** template RLS hides coach-library rows from clients. `client_nutrition_assignment_context` returns only name and source identifiers for a plan the caller owns or can already access. Template-library access is unchanged.
- **Local migration:** `supabase/migrations/20260908150000_client_portal_assignment_context.sql` adds that lookup and notification-route triggers. Applied locally only. Deploying this frontend elsewhere requires the matching migration.

## Running the checks

The browser suite is deliberately separate from general smoke tests because it uses the retained local review fixtures described in the original review. It requires the local app, local Supabase, the Portal Experience Review workspace, and the `.review0908@repsync.test` accounts. It creates new workout/check-in records and an isolated nutrition plan. Check-in tests temporarily adjust only the review client's schedule and restore it in `finally`; the nutrition test removes its new plan afterward.

```sh
npx playwright test --config=playwright.portal-review.config.ts
npx vitest run tests/unit/client-measurements.test.ts tests/unit/notification-route-resolver.test.ts tests/unit/client-checkin-state.test.ts tests/unit/client-checkin-stale-form-contract.test.ts tests/unit/client-checkin-stale-detection.test.ts tests/unit/client-checkins-page-contract.test.ts tests/unit/client-checkins-route-wiring.test.ts
```

The review configuration rejects non-local app URLs. Draft and photo tests use synthetic content. No message is sent to an existing client or coach.

- Targeted lint and the Vite production bundle pass. The full TypeScript build still reports the existing type errors in `src/pages/pt/client-detail.tsx`, including missing onboarding types and incomplete query-result declarations. Those unrelated errors prevent a clean `npm run build`.
