## Behavior and security report

The following completes report topics 5–17; verdict, base, audit and inventory appear above.

5. **Migration/data model:** one forward transaction creates private operation history and append-only deduplicated commercial events. Account/operation identity and one open operation per provider subscription are enforced. Terminal operations cannot reactivate. The operation table begins empty; historical migrations, catalogue values and existing domain rows are unchanged.
6. **Classification:** Launch < Growth < Scale. Higher tier at unchanged cadence and monthly-to-annual at the same/higher tier are immediate. Lower tier at either cadence and annual-to-monthly at the same/lower tier are period-end. Higher tier plus annual-to-monthly is unsupported. Same plan/cadence is a no-op.
7. **Immediate/proration:** immediate PATCH sets `invoice_immediately=true, disable_prorations=false`; period-end uses `false, true`. Preview shows list prices and full annual totals with tax/credit/proration disclosure, never an exact charge quote.
8. **Payment confirmation:** immediate expansion requires verified target identity plus a paid `updated` invoice matching subscription/customer/Store/environment and dispatch timing. Target mapping alone, renewal invoices, old/foreign invoices and failed payment do not complete an upgrade. Recovery can complete the same operation.
9. **Downgrade preflight:** final apply locks the canonical account and counts actual, pending and reserved commitments for clients, staff, workspaces and published packages. Data-quality problems or target overage block apply with totals, excess, remedy and working management links. No destructive cleanup is performed.
10. **Growth ceiling:** positive admissions use the lower finite source/target limit from durable period-end dispatch onward. Ambiguity, manual review and cancellation pending retain the ceiling. Confirmed cancellation or definitive failure clears it. Existing zero/reducing operations retain prior behavior.
11. **Effective date:** the canonical resolver reads the verified scheduled target when due without requiring a punctual webhook. Past-due/grace rules remain applicable; cancellation wins. Pre-effective target renewal-date drift enters manual review and retains the ceiling.
12. **Scheduled cancellation:** only future scheduled changes are cancellable. The server restores the approved source Variant with prorations disabled and verifies it before recording cancellation. Uncertain cancellation stays pending.
13. **Immutable history:** a tier change supersedes the source, inserts the target and relinks the provider atomically; source `plan_version_id` is never rewritten. Cadence-only changes retain the local row. Superseded history grants no access.
14. **Reconciliation:** only the exact approved open operation permits a mapping transition. Third mappings remain manual review. Existing identity, stale-event and snapshot protections run before application. API refresh uses the existing durable inbox with a distinct evidence namespace; it is not represented as signed webhook evidence.
15. **PayPal:** unsupported, as are unknown processors. Provider `stripe` is normalized to the supported card family; there is no direct Stripe integration or PayPal switching URL exposure.
16. **Billing UI:** retains Checkout, Portal, recovery, current entitlements and capacity meters. Adds owner-only preview/confirmation, full annual price, blockers, waiting/scheduled/ambiguous states, cancel and manual refresh. There is no optimistic access expansion or browser-return payment truth.
17. **Permissions/privacy/isolation:** authentication and canonical owner checks precede provider work. Private tables have RLS and no direct runtime grants; security-definer functions have fixed search paths and explicit grants. Safe responses exclude provider IDs, signed URLs, raw provider errors and payment PII. State loads only in Billing; import-isolation tests cover auth, theme, bootstrap/login and callback boundaries.
